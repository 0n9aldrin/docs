# Authentication

PhotoMem uses two authentication methods: **Clerk JWT** for management APIs and **API Keys** for memory operations.

## Clerk Authentication

### Overview
Clerk handles user authentication, session management, and JWT token generation. All organization and project management endpoints require Clerk JWT authentication.

### Getting Started

1. **Sign up** at [PhotoMem Dashboard](https://app.photomem.io)
2. **Complete onboarding** to create your organization
3. **Get JWT token** from Clerk session

### Using JWT Tokens

Include the JWT token in the Authorization header:

```bash
curl -X GET https://api.photomem.io/api/organizations \
  -H "Authorization: Bearer {jwt_token}"
```

### Session Verification

<CodeGroup>
```bash cURL
curl -X GET https://api.photomem.io/api/auth/session \
  -H "Authorization: Bearer {jwt_token}"
```

```javascript JavaScript
const response = await fetch('https://api.photomem.io/api/auth/session', {
  headers: {
    'Authorization': `Bearer ${jwtToken}`
  }
});
const session = await response.json();
```

```python Python
import requests

response = requests.get(
    'https://api.photomem.io/api/auth/session',
    headers={'Authorization': f'Bearer {jwt_token}'}
)
session = response.json()
```
</CodeGroup>

**Response**:
```json

    "fullName": "John Doe",
    "needsOnboarding": false
  },

    {
      "id": "org_xyz789",

      "role": "owner"
    }
  ]

```

## API Key Authentication

### Overview
API keys are used for memory operations (create, read, update, delete, search). They provide project-level access control.

### Creating an API Key

<CodeGroup>
```bash cURL
curl -X POST https://api.photomem.io/api/organizations/{orgId}/projects/{projectId}/api-keys \
  -H "Authorization: Bearer {jwt_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Production API Key",
    "permissions": ["read", "write"],
    "expiresInDays": 365
  }'
```

```javascript JavaScript
const response = await fetch(
  `https://api.photomem.io/api/organizations/${orgId}/projects/${projectId}/api-keys`,
  {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${jwtToken}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      name: 'Production API Key',
      permissions: ['read', 'write'],
      expiresInDays: 365
    })
  }
);
const { apiKey } = await response.json();
```
</CodeGroup>

**Response**:
```json
{
  "apiKey": {
    "id": "key_abc123",
    "key": "pm_live_1a2b3c4d5e6f...",
    "name": "Production API Key",
    "prefix": "pm_live_1a2b",
    "permissions": ["read", "write"],
    "expiresAt": "2025-01-20T00:00:00Z",
    "createdAt": "2024-01-20T15:30:00Z"
  }
}
```

<Warning>
  **Save this key securely!** The full key is only shown once during creation. Store it in a secure location like environment variables or a secrets manager.
</Warning>

### Using API Keys

Include the API key in the `X-API-Key` header:

```bash
curl -X POST https://api.photomem.io/v1/memories \
  -H "X-API-Key: pm_live_1a2b3c4d5e6f..." \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "user_123",
    "userName": "Alice",
    "content": "Loves dark chocolate",
    "tags": ["preference"]
  }'
```

### Key Formats

- **Production**: `pm_live_...` - For production environments
- **Development**: `pm_test_...` - For development/testing

### Permissions

API keys support three permission levels:

| Permission | Create | Read | Update | Delete |
|------------|--------|------|--------|--------|
| `read`     | ❌     | ✅   | ❌     | ❌     |
| `write`    | ✅     | ✅   | ✅     | ❌     |
| `delete`   | ✅     | ✅   | ✅     | ✅     |

### Key Rotation

Rotate keys regularly for security:

```bash
curl -X POST https://api.photomem.io/api/organizations/{orgId}/projects/{projectId}/api-keys/{keyId}/rotate \
  -H "Authorization: Bearer {jwt_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "gracePeriodDays": 7
  }'
```

During the grace period, both old and new keys work. After the grace period, only the new key is valid.

## Security Best Practices

<AccordionGroup>
  <Accordion title="Never expose keys in client-side code">
    API keys should only be used server-side. Never embed them in mobile apps or JavaScript code.
  </Accordion>
  
  <Accordion title="Use environment variables">
    Store API keys in environment variables, not in your codebase:
    ```bash
    PHOTOMEM_API_KEY=pm_live_1a2b3c4d5e6f...
    ```
  </Accordion>
  
  <Accordion title="Rotate keys regularly">
    Rotate API keys every 90 days or when team members leave.
  </Accordion>
  
  <Accordion title="Use least privilege">
    Grant only the permissions needed. Use `read` for analytics, `write` for normal operations.
  </Accordion>
  
  <Accordion title="Monitor key usage">
    Check the last used timestamp regularly to detect unused or compromised keys.
  </Accordion>
</AccordionGroup>

## Error Handling

### Invalid JWT
```json
{
  "error": {
    "code": "invalid_token",
    "message": "JWT token is invalid or expired"
  }
}
```

### Invalid API Key
```json
{
  "error": {
    "code": "invalid_api_key",
    "message": "API key is invalid, revoked, or expired"
  }
}
```

### Insufficient Permissions
```json
{
  "error": {
    "code": "insufficient_permissions",
    "message": "API key does not have 'delete' permission"
  }
}
```
