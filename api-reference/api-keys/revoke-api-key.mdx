---
title: 'Revoke API Key'
openapi: delete /api/organizations/{org_id}/projects/{project_id}/api-keys/{key_id}
---

Revoke an API key immediately. Revoked keys cannot be reactivated and will no longer work for API requests.

<Warning>
This action is permanent and cannot be undone. Any applications using this key will immediately lose access.
</Warning>

## Authentication

This endpoint requires JWT authentication with at least Admin role in the organization.

```bash
Authorization: Bearer YOUR_JWT_TOKEN
```

## Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization
</ParamField>

<ParamField path="project_id" type="string" required>
  The unique identifier of the project
</ParamField>

<ParamField path="key_id" type="string" required>
  The unique identifier of the API key to revoke
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message
</ResponseField>

<ResponseField name="revokedAt" type="string">
  ISO 8601 timestamp of when the key was revoked
</ResponseField>

## What Happens After Revocation

<Steps>
  <Step title="Immediate Effect">
    The API key stops working immediately. Any requests using this key will return a 401 Unauthorized error.
  </Step>
  
  <Step title="Hidden from List">
    The revoked key will no longer appear in the [list API keys](/api-reference/api-keys/list-api-keys) response.
  </Step>
  
  <Step title="Audit Trail">
    The revocation is logged in your organization's audit logs with timestamp and the user who performed the action.
  </Step>
</Steps>

## When to Revoke Keys

<CardGroup cols={2}>
  <Card title="Security Incident" icon="shield-exclamation">
    If a key is compromised or accidentally exposed
  </Card>
  
  <Card title="Employee Offboarding" icon="user-xmark">
    When team members with key access leave
  </Card>
  
  <Card title="Service Decommission" icon="server">
    When shutting down a service that uses the key
  </Card>
  
  <Card title="Regular Rotation" icon="arrows-rotate">
    As part of security best practices (prefer [rotate](/api-reference/api-keys/rotate-api-key) instead)
  </Card>
</CardGroup>

<Note>
If you need to replace a key with minimal downtime, consider using the [rotate API key](/api-reference/api-keys/rotate-api-key) endpoint instead, which allows for a grace period.
</Note>
