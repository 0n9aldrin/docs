---
title: 'Create API Key'
openapi: post /api/organizations/{org_id}/projects/{project_id}/api-keys
---

Create a new API key for a project. The full key is only shown once upon creation - make sure to save it securely.

<Warning>
The full API key is only returned in the creation response. You cannot retrieve it later. Store it securely immediately after creation.
</Warning>

## Authentication

This endpoint requires JWT authentication with at least Admin role in the organization.

```bash
Authorization: Bearer YOUR_JWT_TOKEN
```

## Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization
</ParamField>

<ParamField path="project_id" type="string" required>
  The unique identifier of the project
</ParamField>

## Request Body

<ParamField body="name" type="string" required>
  A descriptive name for the API key (minimum 3 characters)
</ParamField>

<ParamField body="permissions" type="array" default='["read", "write"]'>
  Array of permissions to grant. Options: `["read"]`, `["write"]`, or `["read", "write"]`
</ParamField>

<ParamField body="expiresAt" type="string">
  Optional ISO 8601 timestamp for when the key should expire
</ParamField>

## Response

<ResponseField name="apiKey" type="object">
  <Expandable title="API Key Object">
    <ResponseField name="id" type="string">
      Unique identifier for the API key
    </ResponseField>
    
    <ResponseField name="name" type="string">
      Name of the API key
    </ResponseField>
    
    <ResponseField name="key" type="string">
      **Full API key** - Only shown here, never retrievable again
    </ResponseField>
    
    <ResponseField name="keyPrefix" type="string">
      First 12 characters of the key for identification
    </ResponseField>
    
    <ResponseField name="status" type="string">
      Will be `active` for newly created keys
    </ResponseField>
    
    <ResponseField name="permissions" type="array">
      Array of granted permissions
    </ResponseField>
    
    <ResponseField name="createdAt" type="string">
      ISO 8601 timestamp of creation
    </ResponseField>
    
    <ResponseField name="expiresAt" type="string">
      ISO 8601 timestamp of expiration (null if no expiration)
    </ResponseField>
  </Expandable>
</ResponseField>

## API Key Format

PhotoMem API keys follow this format:

- **Live keys**: `pm_live_` followed by 32 characters
- **Test keys**: `pm_test_` followed by 32 characters

## Security Best Practices

<AccordionGroup>
  <Accordion title="Store keys securely">
    Never commit API keys to version control. Use environment variables or secret management systems.
  </Accordion>
  
  <Accordion title="Use read-only keys when possible">
    If you only need to read memories, create a key with `["read"]` permissions only.
  </Accordion>
  
  <Accordion title="Rotate keys regularly">
    Use the [rotate API key](/api-reference/api-keys/rotate-api-key) endpoint to periodically rotate your keys.
  </Accordion>
  
  <Accordion title="Set expiration dates">
    For temporary access, always set an `expiresAt` date.
  </Accordion>
</AccordionGroup>
