---
title: "Rotate API Key"
api: "POST /api/organizations/{org_id}/projects/{project_id}/api-keys/{key_id}/rotate"
description: "Rotate an API key with optional grace period"
---

## Overview

Creates a new API key and optionally keeps the old key active for a grace period. This allows for zero-downtime key rotation by giving you time to update all services using the old key.

## Authentication

Requires a valid Clerk session token. User must have `admin` or `owner` role in the organization.

## Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization
</ParamField>

<ParamField path="project_id" type="string" required>
  The unique identifier of the project
</ParamField>

<ParamField path="key_id" type="string" required>
  The unique identifier of the API key to rotate
</ParamField>

## Request Body

<ParamField body="gracePeriodDays" type="number" default={0}>
  Number of days to keep the old key active (0-30). If 0, old key is revoked immediately.
</ParamField>

## Response

<ResponseField name="newApiKey" type="object">
  The newly created API key object
  
  <Expandable title="New API Key Object">
    <ResponseField name="id" type="string">
      Unique identifier for the new key
    </ResponseField>

    <ResponseField name="name" type="string">
      Name of the new key (includes "(Rotated)" suffix)
    </ResponseField>

    <ResponseField name="key" type="string">
      **Full API key value** - only shown once!
    </ResponseField>

    <ResponseField name="keyPrefix" type="string">
      First 12 characters of the new key
    </ResponseField>

    <ResponseField name="status" type="string">
      Status (always "active")
    </ResponseField>

    <ResponseField name="permissions" type="array">
      Inherited permissions from old key
    </ResponseField>

    <ResponseField name="createdAt" type="string">
      ISO 8601 timestamp
    </ResponseField>

    <ResponseField name="expiresAt" type="string">
      Always null for rotated keys
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="oldApiKey" type="object">
  Information about the old key
  
  <Expandable title="Old API Key Info">
    <ResponseField name="id" type="string">
      Identifier of the old key
    </ResponseField>

    <ResponseField name="status" type="string">
      Either "active" (during grace period) or "revoked" (immediate revocation)
    </ResponseField>

    <ResponseField name="expiresAt" type="string">
      When the old key will expire (if grace period set)
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="warning" type="string">
  Warning message about updating applications
</ResponseField>

```python Python
import requests

# Rotate with 7-day grace period
response = requests.post(
    f"https://api.photomem.io/api/organizations/{org_id}/projects/{project_id}/api-keys/{key_id}/rotate",
    headers={
        "Authorization": f"Bearer {clerk_token}",
        "Content-Type": "application/json"
    },
    json={"gracePeriodDays": 7}
)

result = response.json()
print(f"New key: {result['newApiKey']['key']}")
print(f"Warning: {result['warning']}")
print(f"Old key expires: {result['oldApiKey']['expiresAt']}")
```

## Rotation Workflow

<Steps>
  <Step title="Request Rotation">
    Call the rotate endpoint with desired grace period
  </Step>
  
  <Step title="Save New Key">
    Immediately save the new API key - it won't be shown again
  </Step>
  
  <Step title="Update Services">
    Update all applications and services to use the new key
  </Step>
  
  <Step title="Verify">
    Confirm all services are using the new key successfully
  </Step>
  
  <Step title="Wait for Expiration">
    If using grace period, old key expires automatically after the set period
  </Step>
</Steps>

## Best Practices

<AccordionGroup>
  <Accordion title="Choose Appropriate Grace Period">
    - **0 days**: For emergency revocations or test keys
    - **7 days**: Standard rotation for production services
    - **30 days**: For complex deployments with many services
  </Accordion>

  <Accordion title="Plan Your Rotation">
    - Identify all services using the current key
    - Schedule rotation during low-traffic periods
    - Have rollback plan ready
    - Monitor error rates after rotation
  </Accordion>

  <Accordion title="Regular Rotation Schedule">
    - Rotate keys every 90 days as standard practice
    - Immediately rotate if:
      - Key may have been compromised
      - Team member with key access leaves
      - After security incident
  </Accordion>
</AccordionGroup>

## Grace Period Benefits

Using a grace period provides:
- **Zero Downtime**: Old key remains valid during migration
- **Safe Testing**: Verify new key works before old one expires
- **Rollback Option**: Can continue using old key if issues arise
- **Time for Updates**: Update services at your own pace
