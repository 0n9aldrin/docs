---
title: 'Delete Memory'
openapi: delete /api/v1/memories/{memory_id}
---

Permanently delete a specific memory. This action cannot be undone.

<Warning>
Deletion is permanent and cannot be reversed. The memory will be removed from all indexes and will no longer appear in search results.
</Warning>

## Authentication

This endpoint requires API Key authentication.

```bash
X-API-Key: pm_live_YOUR_API_KEY
```

## Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization
</ParamField>

<ParamField path="project_id" type="string" required>
  The unique identifier of the project
</ParamField>

<ParamField path="memory_id" type="string" required>
  The unique identifier of the memory to delete
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message indicating successful deletion
</ResponseField>

## What Happens During Deletion

<Steps>
  <Step title="Remove from Database">
    The memory record is marked as deleted in the database.
  </Step>
  
  <Step title="Remove from Vector Store">
    The memory's embedding is removed from the vector index.
  </Step>
  
  <Step title="Immediate Effect">
    The memory immediately stops appearing in search results and list queries.
  </Step>
  
  <Step title="Audit Log">
    The deletion is logged for compliance and auditing purposes.
  </Step>
</Steps>

## Bulk Delete

If you need to delete multiple memories, you can do so in parallel:

```typescript
async function bulkDeleteMemories(
  memoryIds: string[],
  orgId: string,
  projectId: string,
  apiKey: string
) {
  const deletePromises = memoryIds.map(id =>
    fetch(
      `https://api.photomem.ai/api/organizations/${orgId}/projects/${projectId}/memories/${id}`,
      {
        method: 'DELETE',
        headers: { 'X-API-Key': apiKey }
      }
    )
  );
  
  const results = await Promise.all(deletePromises);
  const successful = results.filter(r => r.ok).length;
  
  console.log(`Deleted ${successful}/${memoryIds.length} memories`);
  return { successful, total: memoryIds.length };
}
```

## Error Handling

<AccordionGroup>
  <Accordion title="404 - Not Found">
    - Memory ID doesn't exist
    - Memory was already deleted
    - Memory belongs to a different project
    
    **Note:** Deleting an already-deleted memory returns 404, not success.
  </Accordion>
  
  <Accordion title="401 - Unauthorized">
    - Invalid or missing API key
    - API key doesn't have write permissions
  </Accordion>
  
  <Accordion title="403 - Forbidden">
    - API key doesn't have access to this organization/project
  </Accordion>
</AccordionGroup>

## Alternatives to Deletion

Consider these alternatives before permanently deleting memories:

<Tabs>
  <Tab title="Soft Delete (Custom Tag)">
    Instead of deleting, add a "deleted" or "archived" tag:
    
    ```typescript
    await fetch(`/memories/${memoryId}`, {
      method: 'PATCH',
      body: JSON.stringify({
        tags: [...existingTags, 'archived']
      })
    });
    ```
    
    Then filter out archived memories in your search queries.
  </Tab>
  
  <Tab title="Update with Placeholder">
    Replace sensitive content with a placeholder:
    
    ```typescript
    await fetch(`/memories/${memoryId}`, {
      method: 'PATCH',
      body: JSON.stringify({
        content: '[Redacted by user request]',
        tags: ['redacted']
      })
    });
    ```
  </Tab>
  
  <Tab title="Export Before Delete">
    Back up the memory before deletion:
    
    ```typescript
    // 1. Get the memory
    const memory = await fetch(`/memories/${memoryId}`).then(r => r.json());
    
    // 2. Save to backup storage
    await saveToBackup(memory);
    
    // 3. Then delete
    await fetch(`/memories/${memoryId}`, { method: 'DELETE' });
    ```
  </Tab>
</Tabs>

## Compliance & Privacy

<Info>
PhotoMem takes data privacy seriously. When a memory is deleted:

- All copies are removed from active storage
- Vector embeddings are removed from search indexes
- The memory is marked as deleted in audit logs
- Data cannot be recovered after deletion

For GDPR compliance, deletions are typically processed within minutes, though cache propagation may take up to 1 hour.
</Info>
