---
title: "Create Memory"
openapi: post /api/v1/memories
---

Create a new memory entry for a user. Memories are automatically embedded and indexed for semantic search.

<Info>
  PhotoMem automatically extracts and structures meaningful information from the
  content you provide, making it easily searchable and retrievable.
</Info>

## Authentication

This endpoint requires API Key authentication.

```bash
X-API-Key: pm_live_YOUR_API_KEY
```

## Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization
</ParamField>

<ParamField path="project_id" type="string" required>
  The unique identifier of the project
</ParamField>

## Request Body

<ParamField body="userId" type="string" required>
  Unique identifier for the user (1-255 characters). Can be any format: email,
  phone, UUID, etc.
</ParamField>

<ParamField body="userName" type="string" required>
  Display name for the user (1-255 characters)
</ParamField>

<ParamField body="content" type="string" required>
  The memory content to store. Maximum size: 10KB
</ParamField>

<ParamField body="tags" type="array">
  Optional array of tags for categorization. Maximum 20 tags, each up to 50
  characters.
</ParamField>

## Response

<ResponseField name="memory" type="object">
  <Expandable title="Memory Object">
    <ResponseField name="id" type="string">
      Unique identifier for the memory
    </ResponseField>

    <ResponseField name="userId" type="string">
      User identifier
    </ResponseField>

    <ResponseField name="userName" type="string">
      User's display name
    </ResponseField>

    <ResponseField name="content" type="string">
      The stored memory content
    </ResponseField>

    <ResponseField name="tags" type="array">
      Array of tags (lowercase normalized)
    </ResponseField>

    <ResponseField name="createdAt" type="string">
      ISO 8601 timestamp of creation
    </ResponseField>

    <ResponseField name="updatedAt" type="string">
      ISO 8601 timestamp of last update
    </ResponseField>

  </Expandable>
</ResponseField>

## What Happens Behind the Scenes

<Steps>
  <Step title="Duplicate Detection">
    PhotoMem checks if similar content already exists using both exact hash
    matching and semantic similarity to prevent duplicates.
  </Step>

{" "}

<Step title="Embedding Generation">
  The content is automatically converted into a vector embedding using advanced
  AI models for semantic search.
</Step>

{" "}

<Step title="Indexing">
  The memory is indexed in both the database and vector store for fast
  retrieval.
</Step>

  <Step title="Ready to Search">
    The memory is immediately available for [semantic
    search](/api-reference/memories-api/search-memories).
  </Step>
</Steps>

## Content Size Limits

<Warning>
  Content exceeding 10KB will be rejected with a 413 Payload Too Large error.
</Warning>

If you need to store larger content:

- Break it into smaller, logical chunks
- Store summaries or key points instead of full text
- Use external storage and store references in memories

## Error Handling

<AccordionGroup>
  <Accordion title="400 - Invalid Request">
    - Missing required fields (`userId`, `userName`, or `content`) - `userId` or
    `userName` too long (max 255 characters) - More than 20 tags - Individual
    tag exceeds 50 characters
  </Accordion>

{" "}

<Accordion title="401 - Unauthorized">
  - Invalid or missing API key - API key is revoked or expired
</Accordion>

{" "}

<Accordion title="413 - Payload Too Large">
  - Content exceeds 10KB limit
</Accordion>

  <Accordion title="429 - Rate Limit Exceeded">
    - Too many requests in a short time period - Check your plan's rate limits
  </Accordion>
</AccordionGroup>
