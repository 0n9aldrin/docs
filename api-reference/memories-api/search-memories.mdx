---
title: "Search Memories"
openapi: post /api/v1/memories/search
---

Search memories using semantic similarity. This endpoint finds memories that are conceptually similar to your query, not just keyword matches.

<Info>
  PhotoMem uses advanced AI embeddings to understand the meaning behind your
  query, returning the most relevant memories even if they don't contain the
  exact words.
</Info>

## Authentication

This endpoint requires API Key authentication.

```bash
X-API-Key: pm_live_YOUR_API_KEY
```

## Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization
</ParamField>

<ParamField path="project_id" type="string" required>
  The unique identifier of the project
</ParamField>

## Request Body

<ParamField body="query" type="string" required>
  The search query. Can be a natural language question or keywords.
</ParamField>

<ParamField body="userId" type="string">
  Optional user ID to filter results to a specific user
</ParamField>

<ParamField body="limit" type="integer" default={20}>
  Maximum number of results to return (1-100)
</ParamField>

## Response

<ResponseField name="results" type="array">
  Array of search results, ordered by relevance (highest score first)
  <Expandable title="Search Result Object">
    <ResponseField name="memory" type="object">
      The memory object matching the search
      <Expandable title="Memory Fields">
        <ResponseField name="id" type="string">
          Unique identifier
        </ResponseField>

        <ResponseField name="userId" type="string">
          User identifier
        </ResponseField>

        <ResponseField name="userName" type="string">
          User's display name
        </ResponseField>

        <ResponseField name="content" type="string">
          Memory content
        </ResponseField>

        <ResponseField name="tags" type="array">
          Array of tags
        </ResponseField>

        <ResponseField name="createdAt" type="string">
          Creation timestamp
        </ResponseField>

        <ResponseField name="updatedAt" type="string">
          Last update timestamp
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="score" type="number">
      Relevance score (0-1), where higher values indicate better matches
    </ResponseField>

  </Expandable>
</ResponseField>

## Understanding Relevance Scores

The `score` field indicates how relevant each memory is to your query:

<Card title="Score Interpretation" icon="star">
  - **0.9 - 1.0**: Highly relevant, direct match
  - **0.7 - 0.9**: Very relevant, strong semantic similarity
  - **0.5 - 0.7**: Moderately relevant, related concepts
  - **< 0.5**: Weakly relevant, may not be useful
</Card>

## Best Practices

<AccordionGroup>
  <Accordion title="Write Clear Queries">
    Use natural, specific questions rather than single keywords. "What are
    Alice's coffee preferences?" is better than just "coffee".
  </Accordion>

{" "}

<Accordion title="Filter by User When Possible">
  If you know the user, always include `userId` to improve relevance and
  performance.
</Accordion>

{" "}

<Accordion title="Use Appropriate Limits">
  Request only the number of results you need. Smaller limits return faster.
</Accordion>

{" "}

<Accordion title="Consider Score Thresholds">
  Filter out results with scores below 0.5 for better quality matches.
</Accordion>

  <Accordion title="Cache Search Results">
    Cache frequently used searches to reduce API calls and improve response
    time.
  </Accordion>
</AccordionGroup>

## AI Integration Pattern

Here's how to integrate memory search into an AI conversation:

```typescript
async function getAIResponseWithMemory(
  userMessage: string,
  userId: string,
  orgId: string,
  projectId: string
) {
  // 1. Search for relevant memories
  const memoryResponse = await fetch(
    `https://api.photomem.ai/api/organizations/${orgId}/projects/${projectId}/memories/search`,
    {
      method: "POST",
      headers: {
        "X-API-Key": process.env.PHOTOMEM_API_KEY,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        query: userMessage,
        userId: userId,
        limit: 5,
      }),
    }
  );

  const { results } = await memoryResponse.json();

  // 2. Build context from top memories
  const memoryContext = results
    .filter((r) => r.score > 0.6) // Only use relevant memories
    .map((r) => r.memory.content)
    .join("\n");

  // 3. Send to your LLM with memory context
  const aiResponse = await yourLLM.chat({
    messages: [
      {
        role: "system",
        content: `You are a helpful assistant. Here's what you know about the user:\n${memoryContext}`,
      },
      {
        role: "user",
        content: userMessage,
      },
    ],
  });

  return aiResponse;
}
```
