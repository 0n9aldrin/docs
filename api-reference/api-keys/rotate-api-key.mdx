---
title: 'Rotate API Key'
openapi: post /api/organizations/{org_id}/projects/{project_id}/api-keys/{key_id}/rotate
---

Rotate an API key by creating a new key and optionally keeping the old key active for a grace period. This allows zero-downtime key rotation.

<Info>
Key rotation is a security best practice that should be performed regularly. This endpoint makes it safe and convenient.
</Info>

## Authentication

This endpoint requires JWT authentication with at least Admin role in the organization.

```bash
Authorization: Bearer YOUR_JWT_TOKEN
```

## Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization
</ParamField>

<ParamField path="project_id" type="string" required>
  The unique identifier of the project
</ParamField>

<ParamField path="key_id" type="string" required>
  The unique identifier of the API key to rotate
</ParamField>

## Request Body

<ParamField body="gracePeriodDays" type="integer" default={0}>
  Number of days to keep the old key active (0-30). If 0, the old key is immediately revoked.
</ParamField>

## Response

<ResponseField name="newApiKey" type="object">
  The newly created API key
  
  <Expandable title="New API Key Object">
    <ResponseField name="id" type="string">
      Unique identifier for the new API key
    </ResponseField>
    
    <ResponseField name="name" type="string">
      Name of the new key (original name + " (Rotated)")
    </ResponseField>
    
    <ResponseField name="key" type="string">
      **Full API key** - Only shown here, save it immediately!
    </ResponseField>
    
    <ResponseField name="keyPrefix" type="string">
      First 12 characters for identification
    </ResponseField>
    
    <ResponseField name="status" type="string">
      Will be `active`
    </ResponseField>
    
    <ResponseField name="permissions" type="array">
      Inherits permissions from the old key
    </ResponseField>
    
    <ResponseField name="createdAt" type="string">
      ISO 8601 timestamp of creation
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="oldApiKey" type="object">
  Information about the old API key
  
  <Expandable title="Old API Key Info">
    <ResponseField name="id" type="string">
      ID of the old key
    </ResponseField>
    
    <ResponseField name="status" type="string">
      Either `active` (during grace period) or `revoked` (if no grace period)
    </ResponseField>
    
    <ResponseField name="expiresAt" type="string">
      When the old key will expire (null if immediately revoked)
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="warning" type="string">
  Important message about updating your applications
</ResponseField>

## Rotation Strategies

<Tabs>
  <Tab title="Zero-Downtime Rotation">
    Use a grace period to ensure continuous service:
    
    <Steps>
      <Step title="Rotate with grace period">
        Call the rotate endpoint with `gracePeriodDays: 7`
      </Step>
      
      <Step title="Update applications">
        Deploy the new key to all your applications within the grace period
      </Step>
      
      <Step title="Verify migration">
        Check that the old key's `lastUsedAt` is not updating anymore
      </Step>
      
      <Step title="Automatic expiration">
        The old key will automatically expire after the grace period
      </Step>
    </Steps>
  </Tab>
  
  <Tab title="Immediate Rotation">
    Use when the old key might be compromised:
    
    <Steps>
      <Step title="Rotate without grace period">
        Call the rotate endpoint with `gracePeriodDays: 0`
      </Step>
      
      <Step title="Update applications immediately">
        Deploy the new key to all applications right away
      </Step>
      
      <Step title="Old key revoked instantly">
        The old key stops working immediately
      </Step>
    </Steps>
  </Tab>
</Tabs>
